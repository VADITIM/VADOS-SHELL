# Map

| Path | Purpose |
|---|---|
| `dependencies.md` | Every program, package, module and system interface the shell needs, required or per feature, and what is lost without each; a change that adds one adds its row |
| `shell/shell.qml` | Entry: `Shortcuts`, per screen one `TaskbarWindow`, one `WidgetWindow` (only while `wallpaper.path` is set or that screen has widgets in `widgets.layout`), the `Binding`s that turn `Hardware` and `Weather` polling on for widgets on uncovered screens (`isOnDesktop`), one `CornerWindow`, one `FrameWindow`, one `OverlaySlot` per overlay for all screens (`SearchWindow`, `SettingsWindow`, `DashboardWindow`, `NotificationMenuWindow`, `ScreenshotWindow`), one `PromptPanelWindow` per screen, which builds its window at startup and keeps it unmapped while closed, and a `LazyLoader` per in-shell app window (`CalculatorWindow`) |
| `shell/config/Config.qml` | `shell.json` adapter and setters (`setTaskbarStyle`, `setTaskbarSide`, `setTaskbarCompact`, `setAccent`, `setWindowMode`, `setWeatherLocation`, `setScreenshotFolder`, `setRecordingFolder`, `setReducedMotion`, `setRenderQuality`, `setDoNotDisturb`, `setNotificationsEnabled`, `setProfile`, `toggleFavorite`, `toggleHidden`); validates and migrates the file on load through `utils/Schema.js` and refuses invalid values in setters |
| `shell/config/Appearance.qml` | V/AS tokens: colour (accent read live from `Config`, level bands), font, radius, `liquid` (the goo material: fill, rim and core thresholds), `taskbar`, `settings`, `desktop`, `burst`, `dashboard` (+ `gauge`, `memory`, `weather`), `search`, `activity` (+ `media`, `call`), `capture` (screenshot overlay, toolbar, ink, palette, the recording pill), `lock` (the lock screen: cell gap, blur and detail of the background, drop and fill sizes, the sling's arc and stretch, module sizes, the activity bump, the password field); `bandColor(value, limits)` (lowest band is the accent), `chargeColor(level, isCharging)` |
| `shell/config/Motion.qml` | Every duration and physics constant: `pill`, `hover`, `fold`, `reveal`, `carry`, `settings`, `desktop`, `dashboard` (dim, reveal, polling), `burst`, `press`, `search`, `activity`, `capture` (recording clock, notice, hover dwell and linger, dot pulse, screenshot dim and leave, toolbar), `store`, `supervision` (restart backoff), `attention`, `gesture`, `lock` (the lock's enter and leave, `patience` for PAM), `liquid` (the liquid engine's characters and clock, `sling` for the lock); `isReduced` and `pace()` for reduced motion |

| `shell/windows/FrameTap.qml` | Grabs its window content (`grabToImage`) on every `FrameDebug` capture request and stores it with the screen and side |
| `shell/windows/CornerWindow.qml` | Click-through per-screen window on the top layer that fills the four screen corners outside a small arc (`Appearance.screenCorner.radius`) |
| `shell/windows/WidgetWindow.qml` | The desktop layer: a window per screen below every app window, on `WlrLayer.Bottom` without the wallpaper where the compositor draws its own background (`ownBackground`, driftwm) and on `WlrLayer.Background` with the `Wallpaper` module elsewhere, holding the `WidgetLayer`; click-through except one input `Region` per placed widget (`WidgetLayer.zones`, through a `Variants`); built while `wallpaper.path` is set or the screen has widgets (`wallpaper` and `widgets` rows, surface `desktop`); `isCovered` while that screen's active window is fullscreen |

Where to change things:

- A new surface, or building a planned one: its row in `utils/Features.js`, then the steps in `architecture.md` § Features; its contract is in `roadmap.md`.
- A new module inside a surface (lock module, settings tab, activity): the surface's catalogue row and one file in its folder (`rules/features.md`).
- A new desktop widget: a row in `utils/Widgets.js` (size in cells, the polled `sources` it needs) and its face in `modules/widgets/<Root>.qml` with `isShown` and `isLive`; where widgets sit and how big a cell is: `Appearance.widgets`.
- How fast a surface must show its first content: `Motion.budget.ready`, by impact.
- When the taskbar hides: `Occupancy.qml` (the rule) and `Compositor.qml` (the geometry).
- When an overlay's window exists: always, from startup, one for all screens, moved to the screen it opens on (`windows/OverlaySlot.qml`); `Overlays.isWanted` still says whether a surface is open or leaving. What the shell costs in memory and why: `decisions.md` § Memory.
- Any speed: `Motion.qml`.
- Where screenshots and recordings are saved: `capture.screenshots` / `capture.recordings` (Settings > Settings); the defaults in `Capture.qml`; the recorder and its arguments in `utils/Capture.js`.
- How a surface enters, leaves or recovers from an interruption: its `Lifecycle` handlers (`Burst`); the allowed moves in `utils/Phases.js`.
- What a compositor can do: `utils/Platform.js` and the README "Compositor support" table, together.
- A setting in `shell.json`: its entry in `utils/Schema.js`, the adapter property and a setter in `Config.qml`, a README row (`check-rules.py` keeps the three in step); a changed layout bumps `Schema.version` with a step in `migrations`.
- How anything liquid bounces, wobbles or settles: its character in `Motion.liquid`; the maths in `utils/Liquid.js`.
- Adding a WM: a backend branch in `Compositor.qml` only.
- A process or fetch that must keep working: a `Supervisor` beside it; restart timing in `Motion.supervision`; what the shell says in `Log` calls.
