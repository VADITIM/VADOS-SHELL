# Subsystem interfaces

Who owns each layer, what it may import, what it offers the layers above, and who may call it. Derived from the code (2026-11-07, `direction.md` Phase 1). `tools/check-rules.py` enforces the import columns (`[layers]`, `LAYER_IMPORTS`) and the component token list (`COMPONENT_TOKENS`); the rest is review. Change this file in the same task as the interface.

Data flows down, events flow up: `config → services → components → modules → windows → shell.qml`. `state/` is the only sideways channel; `keybinds/` only flips state or calls a service.

| Layer | Owns | May import (`qs.*`) | Must not import | Called by |
|---|---|---|---|---|
| `config/` | User settings, design and motion tokens | nothing from `qs` | every other layer | everyone (modules read only `Appearance`, `Motion`, `Rendering`) |
| `utils/*.js` | Pure logic with tests, no QML types (`Log.js` alone keeps state: the log ring) | other utils | everything | every layer, by relative `import "../utils/X.js"` |
| `services/` | System and compositor data, no UI | `config`, other services | `state`, `components`, `modules`, `windows`, `keybinds`; any visual type or UI import ✓ | modules (data), state, windows (activation), keybinds |
| `state/` | Shared UI state across features and screens | `config`, `services` | `components`, `modules`, `windows`, `keybinds` | windows, keybinds, `shell.qml` |
| `components/` | Feature-agnostic visual and interaction primitives | `config` (component token groups only ✓) | `state`, `services`, `modules`, `windows`, `keybinds` | modules, tests |
| `modules/` | One user-facing feature each | `config` (`Appearance`, `Motion`), `services`, `components`, `state` | `Quickshell`, `Config`, another module, `windows`, `keybinds` | windows |
| `windows/` | Layer-shell hosts, one per screen (an overlay: one in all, moved to its screen) | everything below | `keybinds` | `shell.qml` |
| `keybinds/` | Global shortcuts and IPC entry points | `config`, `services`, `state` | `components`, `modules`, `windows` | the compositor (shortcuts), `qs ipc call` |
| Compositor adapter | `services/Compositor.qml` + `utils/Platform.js` (+ `utils/Displays.js` and `scripts/outputs.py` for monitor layouts, `utils/Toml.js` for its config) | `Quickshell.Hyprland`, `hyprctl`, `driftwm msg`, the compositor's config files (nowhere else ✓) | | services (`Confinement`, `Occupancy`), `state/Attention`, keybinds, windows (`OverlayWindow`, `TaskbarWindow`, `WidgetWindow`; `SettingsWindow`: background and outputs) |

## config

- `Config` (`config/Config.qml`): `data.<group>.<key>` (the `JsonAdapter` over `shell.json`, schema in `utils/Schema.js`) and one setter per key: `setTaskbarStyle`, `setTaskbarSide`, `setTaskbarCompact`, `setAccent`, `setWindowMode`, `setWeatherLocation`, `setScreenshotFolder`, `setRecordingFolder`, `setReducedMotion`, `setRenderQuality`, `setDoNotDisturb`, `setNotificationsEnabled`, `setProfile`, `setWidgetsLayout` (the whole `widgets.layout` list), `setDashboardWeather`, `toggleFavorite`, `toggleHidden`. Only windows, keybinds, services and state read it; modules get values as properties and send changes up as signals.
- `Appearance`: sizes and colours. **Component-level groups** (any component may read them): `unit`, `radius`, `color`, `font`, `liquid`, `rising`, `burst`. **Feature groups** (only the feature's module, its window, or a service of that feature): `taskbar`, `extension`, `settings`, `desktop`, `widgets` (the desktop widgets' grid and faces; `settings.widgets.grid` points at it for the editor), `dashboard`, `search`, `capture` (screenshot and recording). `choice` (`style`, `isPill`, `outline`, `pill`, `current`, `isCustom`, `pillInk`; from `appearance.choice*`, empty colours follow the accent) is read by the settings module like `color.accent`. A component that needs feature sizes takes them as a `look` property.
- `Motion`: timing and physics, and `pace(duration)`, the reduced-motion precedence. **Component-level**: `isReduced`, `pace`, `stateDuration`, `hoverIn`, `hoverOut`, `press`, `pill`, `type`, `gesture`, `lifecycle`, `burst`, `rising`, `liquid`. **Feature groups**: `highlight`, `capture`, `alerts`, `extension`, `tip`, `hover`, `fold`, `reveal`, `carry`, `settings`, `wallpaper`, `widgets`, `desktop`, `dashboard`, `search`, plus `budget` (`frame`, `sampleShare`, and `ready` by impact: `glance`, `focus`, `takeover`), `store`, `attention`, `supervision` for tests, `StateFile`, `Attention` and `Supervisor`. A component that needs feature timing takes it as a `pace` property.
- `Rendering`: `isLite`, `blur(radius)` (render quality for the rendering components).

## utils: the feature registry

`utils/Features.js` (`rules/features.md`, `architecture.md` § Features): `surfaces`, `origins`, `impacts` (the allowed values), `features` (one row per surface, built or planned) and `overlayKinds()` (key → `{ layer, keepsTaskbar }` for the built overlay rows). Read by `state/Overlays.qml` (`kinds`), `tools/check-rules.py` (`[features]`) and `tst_features`. A module's root named in a row is the interface its window binds (§ modules).

`utils/Alerts.js` (`architecture.md` § Alerts): the alert source catalogue `sources` (`key`, `label`, `glyph`, `tint`, `ids`), `generic`, `glyphs`, and `identify(appName, desktopEntry)`, `plainOf(text)`, `clip(text, limit)`, `leadOf(notifications)`. Read by `modules/alerts/Alerts.qml` and `tst_alerts`. The tints are brand colours, data of the catalogue rather than theme tokens.

`modules/lock/LockPreviews.qml`: `byKey` (catalogue key to the module's `Component`), created by `windows/SettingsWindow.qml` and the preview and passed into `Settings.widgetPreviews`; settings loads each with `isShown` bound, `host` unset.

`utils/Placement.js` (`architecture.md` § Desktop widgets): the grid maths shared by the lock screen and the widgets, catalogue and grid passed in: `sizeOf`, `gridOf(width, height, cell)`, `parse`, `format`, `isInside`, `overlaps`, `isFree`, `fits`, `place`, `remove`, `isPlaced`, `nearestFree`, `firstFree`, `settle`. Read by `utils/Lock.js` (which keeps its own `parse`, `format`, `isInside`, `overlaps`, `fits`, `place`, `remove`, `isPlaced` on its 16 x 16 grid), `utils/Widgets.js` and `tst_placement`. `utils/Widgets.js`: the widget catalogue `widgets` (`key`, `label`, `root`, `columns`, `rows`, `sources`), `sources`, `widgetOf`, `entryOf`, `layoutOn(entries, screen)`, `withLayout(entries, screen, placements)`, `screensOf`, `hasLayout`, `gridOn(width, height, look)`, `originOn`, `rectOf`, `placedOn`, `added`, `removed`, `landing` (the cell a carried widget would take), `moved`, `sourcesShown(entries, screens, look)`. Read by `modules/widgets`, `modules/settings/WidgetEditor.qml`, `windows/WidgetWindow.qml`, `shell.qml` and `tst_widgets`.

`utils/Displays.js` (`architecture.md` § Displays): output objects from `fromHeads(answer)` and `fromHyprland(monitors)`; `transforms`, `rotations`, `scales`, `hertzOf`, `sizeOf`, `rectOf`, `boundsOf`, `overlapOf`, `isTouching`, `isConnected`, `problemOf` (`""`, `empty`, `duplicate`, `mode`, `scale`, `transform`, `position`, `overlap`, `gap`), `withOutput`, `snapped(layout, name, x, y, reach)`, `settled`, `normalized`, `anchored(layout, reference)`, `isSameLayout`, `resolutionsOf`, `refreshesOf`, `modeFor`, `modeText`, `driftwmEntries`, `driftwmText`, `hyprlandRule`, `hyprlandBatch`, `hyprlandConfig`, and the trial `idle`, `begun`, `remaining`, `isExpired`, `isTrial`, `recovery`, `revertText`. Read by `services/Compositor.qml`, `modules/settings/DisplayEditor.qml`, the preview mock and `tst_displays`.

`utils/Capture.js` (`architecture.md` § Screenshot and recording): `folderOf(setting, home, standard, leaf)`, `expand(path, home)`, `stillNameOf(date)`, `motionNameOf(date)`, `clockOf(seconds)`, `recorders` (`key`, `canPause`), `pickRecorder(installed)`, `recordCommand(recorder, screen, file)`, `pauseSignal`, `stopSignal`. Read by `services/Capture.qml` and `tst_capture`. `utils/Ink.js`: the screenshot tool catalogue `tools` and `shapes`, `rectOf`, `isUsable`, `contains`, `clampInto`, `moved`, `strokeOf`, `extended`, `linesOf`, `isHit`, `erased`, `undone`, `nextOf`, `isDrawing`. ## windows

`CalculatorWindow` (a `FloatingWindow`, the one app window; `onClosed` calls `Builtins.close`), `TaskbarWindow` (per screen, `WlrLayer.Top`), `WidgetWindow` (per screen, `WlrLayer.Bottom` under `ownBackground`, else `WlrLayer.Background` with the wallpaper, click-through but for one input `Region` per widget; built while `wallpaper.path` is set or the screen has widgets; reads `Config.data.wallpaper.path` into `Wallpaper` and its screen's `widgets.layout` into `WidgetLayer`, writes moves through `Config.setWidgetsLayout`; `keyboardFocus` OnDemand while `WidgetLayer.wantsKeyboard`, else None), `FrameWindow` (per screen; the frame debugger, outside `Overlays`), `LockWindow` (one `Scope`: the only `WlSessionLock`, `locked: Lock.isLocked`, a `LockScreen` per lock surface, the password draft; after an unlock a click-through `WlrLayer.Top` window per screen for `LockLeave`; holds and releases the taskbars through `Overlays`) and the `OverlayWindow`s (`SearchWindow`, `SettingsWindow`, `DashboardWindow`, `NotificationMenuWindow`, `ScreenshotWindow`; `overlayKey`, `isOpen`, `parts`, `canHandOff`, `phase`, `requestClose()`, `land()`, `placeVisitor()`). Windows are the only place that bridges `Config` setters to module signals and reports overlay phases to `Overlays`. Created only by `shell.qml` through `Variants`: the taskbar and frame windows directly, each overlay window inside an `OverlaySlot` (`overlayKey`, the window as its default `surface` component), which builds it at startup and keeps it, unmapped while closed. `SettingsWindow` turns `GitHub.isActive` on only while settings is present. An `OverlayWindow` is therefore always built closed: `isOpen` stays false until the window is complete (`isComplete`), so its module sees the same closed-to-open change as before.

## keybinds and IPC

`keybinds/Shortcuts.qml`: global shortcuts `vados:frames`, `vados:frameShot`, `vados:screenshot`, `vados:record`, `vados:search`, `vados:settings`, `vados:dashboard`, `vados:activity`, `vados:notifications` (opens the notifications menu; Hyprland protocol), `vados:lock`, and `qs ipc call` targets `lock` (`lock`, `status`; there is no unlock), `frames` (`toggle`, `step`, `back`, `shot`, `close`, `status`), `dashboard`, `search`, `settings`, `desktop`, `overlay`, `activity`, `attention`, `diagnostics`, `notifications`, `screenshot` (`shoot`, `close`), `recording` (`toggle`, `pause`, `stop`, `status`). It opens the `screenshot` overlay when `Capture.shot` reports the frozen frame, and ignores a new shot while one is up on that screen. Each handler flips `state` (`Overlays`, `ActivityState`, `Attention`), calls a `Config` setter, or calls a service (`Confinement`, `Notifications`, `Capture`). No feature logic.

## Compositor adapter

`services/Compositor.qml` is the only file that knows which compositor runs. It publishes `capabilities` (`utils/Platform.js`, one row per backend) and `level` (`core`, `extended`, `native`). Everything else asks a capability:

| Capability | Asked by |
|---|---|
| `windowControl` | `Compositor.send` (commands go nowhere without it), `Confinement.maximize`, `Confinement.fullscreen`, `Confinement.canConfine` |
| `freeCanvas` | `Confinement.canConfine` → settings mode buttons (`canSwitchMode`), Desktop mode |
| `windowMinimize` | `Confinement.canMinimize` → `minimize()` |
| `windowSnap` | `Confinement.canSnap` → `snap()` |
| `activeWindow`, `windowGeometry`, `fullscreenDetection` | published as `activeWindow`; `Occupancy` hides the taskbar and `Attention` holds notifications from it |
| `focusTracking` | published as `focusedScreen` (the first screen without it) |
| `workspaceManagement` | nothing yet; no backend has it |
| `layerShell` | required by the shell itself |
| `sessionLock` | `Lock.canLock`; the `lock` row `needs` it; without it `Power.lock()` hands over to `loginctl lock-session` |
| `displayPower` | `Compositor.powerDisplays` (the lock's blanking); without it the locked screen only turns black |
| `outputConfiguration` | `SettingsWindow` (`canConfigureDisplays`: the Displays sub tab), `Compositor.readOutputs`, `Compositor.applyOutputs` |
| `ownBackground` | `WidgetWindow` (the bottom layer and no shell wallpaper) and `shell.qml` (a window only for screens with widgets); without it the shell draws the wallpaper on the background layer |

The README section "Compositor support" lists the same table with what degrades; `tools/check-rules.py` fails when it and `Platform.js` disagree.
