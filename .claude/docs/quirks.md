# Quirks

- **`Supervisor` reads a stop one timer tick later** (2026-11-07): it is unverified whether Quickshell's `Process` emits `exited` before or after `runningChanged`, and a failed start emits no `exited` at all. A zero-length timer after `runningChanged` sees both, so the failure says `exited with code N` or `failed to start` either way.
- **`Log.js` is one instance only if every importer resolves to the same file URL.** All shell files import `"../utils/Log.js"`, which is the same file in Quickshell; the tests import it by another path (`../../shell/utils/Log.js`), so `tst_log` has its own ring, separate from the one the components log into. Within one engine, an identical message within `Log.repeatWindow` is held back, so a test that expects a warning (`ignoreWarning`) must use a message no earlier test printed (unique supervisor names in `tst_supervisor`).

- **`Config` repairs a tick after `FileView.loaded`** (`Qt.callLater`, 2026-11-07), because it is unverified whether `JsonAdapter` reads the file before or after `loaded` is emitted; repairing first would be overwritten by the raw values. For that tick a bad value is what `JsonAdapter` coerced it to.
- **The schema's `fallback` and the adapter's literal default are written twice on purpose**; `check-rules.py` compares them as text, so write both the same way (`"left"`, `[]`, `false`).

- **`Burst.wallOutline` is traced, not bound** (2026-11-07). It is set in `trace()` once per frame, so for one frame after the wall appears it can be empty while `hasWall` is already true; read it with a length check (`cornerSplashForm` does). `farFront` is traced with it.
- **`tst_budget` numbers are from this container, offscreen.** They budget script work only; a slower CPU or the real compositor's rendering are not in them. The suite prints the measured 95th percentile and worst frame on every run.

- **A `Lifecycle` host captures in `moving`, starts in `moved`.** Reading `form` after the phase changed already gives the leave form, and a reduced-motion animation started before the phase changed reports to the old phase and is lost (2026-11-07).
- **Never stop an animation from its own final `ScriptAction`.** The lifecycle hosts only stop animations on `settle`, never on `entered` or `exited`.
- **Never name a component `Transition` or `State`** (like `Drag`): QtQuick types win inside `qs.components`. The lifecycle component is `Lifecycle`, and inside it the move table is imported as `Phases`.

- **Never name a component `Drag`.** QtQuick's attached `Drag` type wins over a same-named file inside `qs.components` itself ("Drag is only available via attached properties"), while files importing `qs.components` later get the local one. The gesture ability is `Gesture` for that reason (2026-11-07).
- **A `Scope` or `Singleton` must not declare `property var data`.** `data` is their default property; shadowing it sends every child (`FileView`, `Timer`) nowhere. `StateFile` calls its state `values`.
- **`Config` must not bind to `Motion` at construction.** `Motion.isReduced` reads `Config`, so `Config`'s write timer takes `Motion.settings.write` when `setAccent` runs instead of in a binding, to avoid a singleton construction cycle.
- **Singletons are created on first use**, so anything that must listen from startup is touched by `Shortcuts` (`Notifications`, `Attention`). The tests touch `Attention` the same way before sending notifications.
- **Preview: the fake `Singleton` needs a default property** (`tools/preview/play.py`), or a state singleton with child `Timer`s fails to load.
- **Tests: QML `XMLHttpRequest` cannot read files synchronously**, so the fake `FileView` reads and writes through a Python `Disk` singleton registered by `tools/tests/run.py`.
- **Liquid characters must be underdamped** (`damping` below 1). `Liquid.swing` takes `√(1 − damping²)`; at 1 or above it is NaN and the body vanishes. Liquid always overshoots, so a non-overshooting motion is an easing, not a character.
- **`Mutate`'s pop snaps the last 1.2 %.** The spring has not fully settled when the pop clock (`Motion.pill.pop`) ends, so `pop` reads 1 from then on; the snap is under half a pixel on a task pill.
- **Characters are in seconds.** `Burst` converts their phase share to seconds (`openTime`, `spreadTime`) before calling the engine. Retuning `Motion.burst.spread` or `Motion.settings.pop` now changes how much of the spring plays, not the spring.
- **Unverified Quickshell assumption (notifications, 2026-11-06):** singletons are created on first use, so `Shortcuts` binds to `Notifications.isServing` to create the service and register the server at startup. `LazyLoader` with a `NotificationServer` child and `trackedNotifications.values` as an array are also untested.
- **Preview on Linux** (cloud sessions): PySide6 needs `libegl1`, and the offscreen platform draws each `LiquidLayer` as an unmasked grey slab, so goo shapes cannot be judged there. Content, layout and runtime warnings can: run `play.build()` and load `play.qml` with `QT_QPA_PLATFORM=offscreen`.
- **`long` is a reserved word in QML JavaScript.** `const long = …` makes the file fail to parse, and `qmlformat` exits 1 without a message.
- **The preview harness cannot time animations.** `grabWindow` under the basic render loop lets every animation finish within one frame, and the threaded loop stalls while grabbing. Check motion by setting the phase properties by hand and grabbing poses.
- **The dashboard body uses per-corner `Rectangle` radii** (`topLeftRadius` and friends), which need Qt 6.7 or newer.
- **A Quickshell window's `visible` reads `false` while it is being created.** The getter switches from the requested value to the backing window's `isVisible()` as soon as the backing window exists, before it is shown. `onVisibleChanged: if (!visible) close()` therefore closed the settings window during its own creation, and the `LazyLoader` destroyed it before it appeared. Use `onClosed` instead (the old floating settings window hit this): it fires only when the user, the compositor or an error closes the window, never on creation or on a programmatic hide.
- **Unverified Quickshell assumption (settings, 2026-11-05):**
  - Changing `PanelWindow.anchors` at runtime (taskbar side) re-anchors the layer surface without a restart.
- **The fold gesture fires mid-drag, once per press.** Folding hides the pressed idle, whose `FoldDrag` is then disabled and cancelled, so waiting for the release would never fire. `hasFolded` also swallows the click a kept idle (audio, power) would get on release.
- **Preview: slow motion by patching the built `Motion.qml`.** Multiplying `burst.converge`, `spread`, `impact` and `leave` in the build tree before loading `play.qml` makes timed `grabWindow` frames usable for the burst (scratch `shot.py`, 2026-11-05).
- **The input mask is not inside the mirrored module.** `Region { item }` mapping through an item transform was not trusted, so `TaskbarWindow` places its own `inputZone`.
- **Preview: `QQmlExpression` cannot see singletons** imported by the preview root (`Appearance`, `Config` evaluate to undefined). Read values through a root child (`settings.accent`) instead. Build the expression on `QQmlEngine.contextForObject(window)`, not `engine.rootContext()`, or ids are undefined too.
- **`long` and `short` are reserved words in the QML parser**, even as JavaScript `const` names. `qmlformat` then fails with no message.
- **Preview: `PySide6.scripts.qml` imports every `.py` file next to the QML file it runs.** Keep preview QML drivers in a folder without Python scripts, or one of them may create a second application.
- **Preview: large liquid layers drop to about 1 fps**, so animations jump to their end. Judge the settings morph from posed values (set `merge`, `hop`, `shoot`, `pop`, `bud`, `extend`, or `leaveFrom` + `isLeaving` + `collapse`/`back`, on a `Settings` whose `isOpen` stays false), not from timed screenshots.

- **Preview typing.** `QTest.keyClicks` does not accept a QQuickWindow. Use `QTest.keyClick(window, character)` per character.
- **Goo hides tiny shapes.** A shape smaller than about the blur radius never crosses the threshold on its own.
  - `LiquidLayer` also draws the raw shapes, so small droplets still show, but without a rim.

## Waves on a leaving burst (2026-11-09)

`crestHeight()` is zero while the burst is leaving. The crest shape is hidden then but the troughs of `edgePoints` still ran when a leave began before the impact finished, and rounded corners turned them into loose arches at the wall corners.

## Risers on a leaving burst (2026-11-09)

The top and bottom risers (`stepForm`) have square left corners and a height of `rise + stepCorner` even when `rise` is small, so on a collapsing dashboard they stuck out of the rounded corners and stayed as a vertical stem. They retract within `Motion.burst.stepRetract` of the exit.

- **Overlay registration order (2026-11-09).** `Overlays.open` registers the new overlay before it closes the displaced ones. Closing first lets the old overlay react synchronously, find no overlay on the screen and return the taskbar mid-swap (`tst_overlays`).

- **A swap knows its circle before the overlay shows (2026-11-09).** `Overlays.hasCircle` is true for the waiting overlay from the start of the swap, not when the first overlay lands. `isOpen` and `hasCircle` reach a `Burst` through separate bindings, and `prepare()` latches `startsFromCircle` when the show arrives; learning it late made the taskbar parts fly to the centre. Unverified live on driftwm.
- **A swap knows it hands over before it closes (2026-11-09).** `Overlays.isHandingOver` is true for every overlay but the target from the moment the swap is placed, not once the leaving overlay is out of `screens`. That removal also flips `isOpen`, and `startLeave()` latches `isSwapped`; when the close binding won the race, the leave played as a release and streamed the taskbar parts home mid-swap, so the taskbar showed between dashboard and search (`tst_overlays`). Unverified live on driftwm.
- **The preview wires overlays by hand (2026-11-09).** `tools/preview/play.qml` hosts the overlay modules without `OverlayWindow`, so it repeats that wiring: `isOpen` gated by `isWaiting`, `isHandingOver`, `hasCircle`, `reportPhase` on `phase`, and `settleSwap` plus `returnTaskbar` on `landed`. Search and dashboard once lacked it, so in the preview a swap never happened: search gathered the taskbar parts afresh while the dashboard was still leaving, which looked like the taskbar showing mid-swap. A change to `OverlayWindow` goes into `play.qml` too (`tst_preview`).
- **A change handler can run before the bindings on the same property** (2026-11-09). `Settings.onTabChanged` read `subTabs` (bound to `tab`) and got the old tab's list, so reopening settings from Advanced kept `subTab` at `vados` and its page showed on the home page. Handlers compute from the changed value itself (`subTabsByTab[tab]`), never from a binding that depends on it.
- **Without Space Mono installed the mono font falls back to a proportional one and shapes ligatures** (Windows preview), which breaks ASCII art. The settings banner uses `Appearance.font.fixedMono` (first installed of `monoFallbacks`, via `Qt.fontFamilies()`) and turns shaping off (this Qt's QML fonts have no `fixedPitch`, `styleHint` or `families`), so it stays on a grid.

- **Telegram's desktop id ends in `.desktop`** (`org.telegram.desktop`). `utils/Alerts.js` tries every name as given and also without a trailing `.desktop`, never only stripped, or Telegram's own id would become `org.telegram`.
- **`String.prototype.trimEnd` is missing in the shell's JavaScript** (Qt 6.8 V4 in the tests threw `not a function`); `Alerts.clip` drops trailing spaces by hand. Regular expression literals are refused by the code-style hook (their flags read as abbreviations), so `utils/Alerts.js` scans characters instead.
- **A QML function with typed parameters and no return type warns when it returns a value** (`should be coerced to void`), which fails `tst_preview`; the preview's `postSample` is untyped for that reason.
- **Qt 6.12 copies a plain JavaScript object passed through a `var` signal parameter** (2026-11-10, PySide6 6.12 on Linux; the Windows harness ran 6.8). The receiver gets a new object with its keys sorted, so `list.indexOf(notification)` was -1 and no test notification ever peeked: six `tst_attention` and `tst_preview` cases failed on this machine. Real notifications are QObjects and keep their identity, but matching by `id` holds for both.
- **A `Repeater` or `ListView` over a JavaScript array rebuilds every delegate when the array changes**: every row enters again, and a row whose own signal handler changed the array is destroyed while that handler still runs (`Attempted to evaluate an expression in an invalid context`, about one preview run in six). The notifications menu keeps a `ListModel` in step with `Notifications.history` by `key` (`syncRows`: remove what is gone, insert what is new) and forgets a swiped row from the menu's context (`Qt.callLater`).
- **QtTest's `init()` is blocked by the code-style hook** (`init` reads as an abbreviation); `tst_activity` resets at the start of each test through a `quiet()` helper instead.
- **Search opens on a bare Super tap in driftwm** (2026-11-10). driftwm 0.21 takes a bare modifier chord (`"super"`) as a tap binding fired on release, so `super+<key>` and `super`+mouse bindings keep working. Bind it with `spawn`, not `exec`: `exec` shows a loading cursor and leaves fullscreen.

## `IconPaths.js` is generated (2026-11-10)

`shell/utils/IconPaths.js` is written by `python -I tools/icons/build.py` from `tools/icons/source/*.svg`; a hand edit is lost on the next build. The builder reads `path` and `circle` elements, sums `translate` transforms, rescales the `viewBox` to 24 and keeps relative commands relative; it does not handle `rect`, `polygon`, `scale` or `rotate` transforms or packed arc flags (`a1 1 0 011 1`). An element is stroked if any ancestor sets `stroke`, otherwise filled unless `fill="none"`.

## Notifications menu (2026-11-10)

- **Blip's command line is unverified beyond `--help`.** Blip 1.2.6 (`/opt/blip`, a JVM app) lists `--peer=<value>`, `--file=<text>`, `--background` and `--delay`; what a peer value is (a device name, an id) and whether a running Blip takes the file instead of starting a second window are not known. `Transfer` runs one `blip` per file.
- **The file chooser is the portal's, through Python.** Quickshell has no D-Bus call API, so `scripts/pick-files.py` (python3 with `gi`, which Arch ships with GTK) calls `org.freedesktop.portal.FileChooser.OpenFile` and waits for the `Response` signal on its request path (`/org/freedesktop/portal/desktop/request/<sender>/<token>`). A cancelled chooser prints nothing and nothing is sent.
- **The bubbles' liquid is reparented.** Each bubble is a `Turn` outside the liquid layer (so its glyph sits on top and mirrors with `edgeX`), and its `LiquidShape` sets `parent` to the burst's flipped frame inside the layer, in the unmirrored frame. `Repeater.itemAt` from inside the layer was not used: it is not notifiable.
- **A released delegate's animation can outlive its context.** When a `Repeater` or `ListView` drops a delegate, Qt invalidates its QML context at once but deletes the item later; a `SequentialAnimation` still running in it can reach its `ScriptAction` in between, which logs `QQmlExpression: Attempted to evaluate an expression in an invalid context` (gdb: `QQmlExpression::evaluate` from `QSequentialAnimationGroupJob::activateCurrentAnimation`). It showed in about one preview run in four once the menu's tests changed activities while faces were leaving. `Turn` and `Mutate` stop their animations in `Component.onDestruction`, which runs when the context is torn down; 10 preview runs were clean after. No deterministic test: the race needs an animation tick before the deferred delete.
- **Offscreen grabs do not render the liquid layer**, so the split was checked by drawing `Burst.bodyPieces` over the grabs (red outlines) at 120, 260, 420, 620, 900 and 1600 ms.
- **driftwm reports no focused window while a layer surface holds the keyboard.** With an overlay open, `driftwm msg state` lists every window with `is_focused: false`; focus comes back to the window that had it about 20 ms after the overlay releases the keyboard. Hyprland's `activewindow` likely does the same for an exclusive layer (unverified); there `Compositor.lastWindow` is simply the last active window, without checking it is still open.
- **The frame debugger does not pause `Timer`s** (`veilDelay`, `linger`), so frames stepped with `KP_0` show the taskbar's veil early; and the nested `driftwm --backend winit` captures about one frame a second with `grim`, too slow to judge timing. Real-time checks were made on the live session with `grim -o <output> -s 0.3`.

## Clipboard history (2026-11-11)

- **Unverified on a real session**: that `wl-paste --watch` gives the child the clipboard on stdin and inherits its stdout (the reader drains stdin and prints to stdout); that `CLIPBOARD_STATE` is set (wl-clipboard 2.2 and later; older versions leave it unset and the reader asks for the types instead); that KeePassXC offers `x-kde-passwordManagerHint` with the value `secret`; that `wl-copy` reading stdin from a Quickshell `Process` (`stdinEnabled`, `write`, then `stdinEnabled: false`) gets the end of input and forks to serve the selection.
- **Copying from the shell comes back as a new copy.** `wl-copy` owns the selection and the watcher sees it; `Clipboard.add` moves the existing entry up instead of adding one.
- **An image copy that also offers text is kept as text** (a browser offers both for an image with alt text or a URL).
- **The secret check is a guess.** Known token prefixes (GitHub, AWS, Slack, OpenAI-style `sk-`, Google, GitLab, JWTs, private keys) are certain; a single word of 12 or more characters with lower and upper case, digits and symbols, or 24 or more with three of those and digits, counts as a secret too. A long camel-case identifier with digits can be masked by mistake.
- **`Supervisor.stop()` restarts a running process** (it marks the stop as asked and starts again while active); `Clipboard` uses that to pick up a changed `clipboard.images`.
- **`Appearance` groups reference their parent by the root property name** (`activity.expanded.factor` inside `media`): unqualified names resolve against the root object of the singleton.

## Memory (2026-11-11)

- **Resident memory is not what the shell uses.** With `transparent_hugepage/enabled = always` the kernel maps library text as huge pages, so every touched 2 MB of LLVM, Mesa, the NVIDIA EGL libraries and Qt counts as resident in every process that maps it. An empty `ShellRoot {}` shows 311 MB resident and 99 MB proportional (`Pss` in `/proc/<pid>/smaps_rollup`). Compare `Anonymous`, not `Rss`, when judging a change.
- **libglvnd loads NVIDIA's EGL before Mesa's** (`/usr/share/glvnd/egl_vendor.d/10_nvidia.json`), and it stays mapped (about 100 MB resident) even when every screen runs on the AMD GPU. `__EGL_VENDOR_LIBRARY_FILENAMES=/usr/share/glvnd/egl_vendor.d/50_mesa.json` skips it.
- **jemalloc's defaults keep what the shell frees.** Each thread gets its own arena (64 on 16 CPUs); freed pages are returned only when that arena is used again, and the arenas of render threads that ended never are. With huge pages on, a partly used 2 MB extent is resident in full. After opening and closing every overlay once the shell held 110 MB more than before, although its windows were destroyed and jemalloc counted only 17 MB more allocated. `thp:never,narenas:4,background_thread:true` brings that to 40 MB.
- **`//@ pragma Env` is too late for `MALLOC_CONF`** (and for `GLIBC_TUNABLES`): the process is running by the time Quickshell reads `shell.qml`. It does work for variables read later, such as the EGL vendor list.
- **A hidden `PanelWindow` gives its render thread back** (probe: a second window shown and hidden again; `QSGRenderThread` count 1, 2, 1). What stays resident after an overlay has closed is the allocator's, not a window's.
- **Measuring.** A second instance (`qs -p <path>`) runs beside the live one and takes `qs ipc --pid <pid> call ...`; it draws a second taskbar while it runs. A copy of `shell/` with `Variants` blocks removed from `shell.qml` gives the cost of each window. For the heap, start it under gdb with `MALLOC_CONF=prof:true,lg_prof_sample:15,prof_prefix:<path>`, stop it with a signal and `call (int)mallctl("prof.dump",0,0,0,0)` and `call (void)malloc_stats_print(0,0,0)`; attaching to the live shell is refused (`ptrace_scope` 1). Never pipe the measuring script into `head`: it dies before it kills its instance.
- **PySide6 is not installed system-wide on the Linux machine** (2026-11-11), so `tools/tests/run.py` does not start with the system Python; a virtual environment does (`python -m venv <dir> && <dir>/bin/pip install PySide6`, then `QT_QPA_PLATFORM=offscreen <dir>/bin/python tools/tests/run.py`; Qt 6.12, all but the pre-existing `test_fullscreenStillPeeks` pass). The suite runs with Qt's own `/usr/lib/qt6/bin/qmltestrunner -import <build> -input tools/tests` after `run.build()`, with a QML stand-in for `VadosTest` (`Clock`, `Disk`); the `StateFile` tests and one `Confinement` test need the real `Disk` and fail under the stand-in.
- **A pointer handler declared inside a `Flickable` lands on its `contentItem`**, not on the `Flickable` (Qt 6.12; its `parent` is the `contentItem` and cannot be set to the view). `Drift` therefore finds its view as `parent.parent`, and it only takes wheel events over the content: over a margin (`topMargin` of the search list) or a view shorter than its content area, the wheel falls through to Qt's own step.
- **Qt 6.12 gave `Item` the properties `top` and `bottom`** (2026-11-11, Arch `qt6-declarative` 6.12.0). A `readonly property real top` or `bottom` on an `Item` fails with "Cannot override FINAL property" and the whole shell does not load; the PySide6 preview on Windows is older and accepts it. Name such properties for what they are (`clipTop`, `clipBottom` in `TaskClip` of `Dashboard.qml`).
- **`tryCompare(array, "length", …)` never sees a replaced array** (2026-11-11): QML array properties are replaced, not mutated, so the test holds the old one. Compare with `tryVerify(() => Service.list.length === n)`.
- **A screenshot must be taken before its overlay maps**: screencopy includes layer surfaces, so a frame grabbed with the dim up is dim. `Capture.shoot` runs grim first and only its `shot` signal opens the overlay; a second PRINT while the overlay is wanted is ignored (`Shortcuts.shoot`).
- **A `Gesture` instance must not declare its own `onPositionChanged`**: it would replace the handler `Gesture.qml` uses to track the drag. Read the pointer with a `HoverHandler` beside it (`Screenshot.qml`).
- **driftwm binds PRINT itself.** Unbound, its defaults run `grim - | wl-copy` on PRINT (nothing visible) and `slurp` on SHIFT+PRINT (a white overlay that ends on release), which looks like a broken shell screenshot. The user's config must bind both to the shell's IPC (README driftwm block); reload with `driftwm msg action reload-config`.
- **A `LiquidShape` must be parented into `liquid.shapes`** (`parent: liquid.shapes`). Declared as a plain child of a `LiquidLayer` it is a sibling of the passes and draws as the raw white mask on top: the first screenshot toolbar was a white pill for this reason.
- **The offscreen test harness draws no liquid**: a `LiquidLayer` grabbed in `tools/tests` shows only the background (MultiEffect passes do not render there), so the liquid's colour can be checked only on a real screen (`grim` while the surface is up).
- **`gesture.pressPoint` (and any `point` property) is a live value-type reference.** Kept in a stroke or rect as is, it follows the next press and moves old strokes; copy it into a plain `{ x, y }` first (`Ink.pointOf`).
- **An enabled `HoverHandler` over the taskbar steals hover from the `MouseArea`s under it.** The alert content stays over the activity pill after a peek ends, and its handler kept the recording pill from expanding on hover (`tst_preview`); `Alerts` enables it only while the content is shown.
