# State rules

Enforced by `tools/check-rules.py` where marked ✓.

- **Two kinds of saved state, two places.** User choices live in `shell.json`, written only by `config/Config.qml` ✓ (each key has a setter and a README row ✓). Runtime state (history, parked windows, notification and clipboard history) lives in `~/.cache/vados/<feature>.json`, written only through a `StateFile` ✓ (`services/StateFile.qml`).
- **The compositor's config is written only by `services/Compositor.qml`** ✓ (user, 2026-11-13): the wallpaper picked in settings goes into driftwm's `config.toml` (`[background]`), and the Displays tab's layout into its `[[outputs]]` entries (`scale`, `transform`, `position`, `mode` of the listed monitors), changing only the keys it sets (`utils/Toml.js`); on Hyprland a kept layout goes into `hypr/vados-displays.conf`, a file only the shell writes. No other file outside `shell.json` and the cache is written, except the boot setup (below).
- **The boot setup is written only by `scripts/boot.py apply`, as root through `pkexec`, on the user's BOOT switch** (user, 2026-11-17): the mkinitcpio presets' `--splash`, the `plymouth` hook in `/etc/mkinitcpio.conf`, `quiet splash` in `/etc/kernel/cmdline`, `Theme=` in `/etc/plymouth/plymouthd.conf`, and the assets under `/usr/share/vados/boot` and `/usr/share/plymouth/themes/vados`. The new file contents are planned by the pure `utils/Boot.js` (`tst_boot`); the script accepts only those paths, backs them up to `/var/lib/vados/boot`, keeps the previous boot image and writes everything back when the rebuild fails. What it added is recorded in the `boot` `StateFile`, so OFF removes only that.
- **`shell.json` is validated against one schema** ✓ (`utils/Schema.js`, direction rule 6). Every key is in the schema, the `Config` adapter (same default) and the README, and every setter checks its value with `accept()` against the schema ✓. On load a wrong type or a value outside its choices falls back to the default and is logged once (`vados: config:`); unknown keys are logged and ignored; the file is written back only after a migration or a repair. A changed layout bumps `Schema.version` together with a step in `Schema.migrations`; a file without `version` is version 0.
- **A `StateFile` is versioned.** Bump `version` only together with a reader for the old version; a file with another version, or one that does not parse, is kept aside (`.version<N>`, `.corrupt`) and the feature starts from its defaults. A file without a version is read as plain data (pre-`StateFile` files).
- **Losing state never strands the user.** Anything that changes the desktop (parked windows, an output layout on trial) is saved as it happens and recovered on start (`Confinement.recover`, `Compositor.recoverOutputs`), and startup never waits on a state file.
- **Writes are debounced** (`Motion.store.write`) and flushed when the owner is destroyed.
